## [1.7.4] 🐝 — 2026-08-15

### 🐞 Fixed

- Watch mode now also watches every folder listed in `config.json`, not just
  the category roots. Files dropped **directly into a configured subfolder**
  (e.g. `videos/`) are picked up and processed instead of being silently
  ignored, because the watcher previously only fired the pipeline when the
  organizer had moved at least one loose file from the root.
- The size-gate in the heavy processor no longer clobbers an existing file that
  shares the target's base name: if `abc.mp4` already exists in `heavy/`, a
  re-encoded `abc.3gp` keeps a timestamped variant instead of overwriting it.
- The ffmpeg/ffprobe availability check is no longer cached for the whole
  process when it fails: if the binaries become available mid-session (e.g. a
  container still starting up), `--watch` / `--skip-watermark` runs detect them
  on the next `.3gp` instead of staying stuck on a stale negative result.
- A file that vanished or became unreadable between the folder scan and the
  send (a watch-mode race, e.g. the organizer moving it first) is now reported
  as a failed send instead of crashing the pipeline and being quarantined to
  `_failed/` as if it were a corrupt file.
- The startup ffmpeg check now also scans every root's `heavy/` folder for
  forced-mp4 containers (`.3gp`). Previously, in `--skip-watermark` runs, only
  the folders listed in `config.json` were checked, so an oversized `.3gp`
  moved to `heavy/` by the organizer was skipped silently by `--process-heavy`
  when ffmpeg was missing.
- Added global error handlers: a stray promise rejection no longer takes down a
  long-running `--watch` session (it is logged and processing continues), and
  an uncaught exception triggers the normal cleanup path (kills ffmpeg
  children, removes temps, destroys the client) before exiting.

## [1.7.4] 🐝 — 2026-08-11

### 🐞 Fixed

- Transcoded files are now uploaded with the extension of their actual output:
  a `.3gp` re-encoded to `.mp4` (or a `.avif`/`.bmp`/`.tiff` normalized to
  `.jpg`) used to be sent under its original name, so Discord detected it by
  the extension of the attachment and showed a perfectly good mp4 as a plain
  downloadable file.
- `.3gp` videos are now converted to a real `.mp4` even when running with
  `--skip-watermark`: Discord cannot render the 3GP container inline at all,
  so a byte-for-byte copy would always appear as a plain file. The conversion
  reuses the quality-first encode pipeline (CRF + copied audio) but without the
  logo overlay. Other containers (`.webm`, `.mov`, `.mkv`, …) are still copied
  as-is when watermarking is skipped.

## [1.7.3] 🪱 — 2026-08-11

### 🐞 Fixed

- `.3gp` files are now recognized as videos, so the organizer routes them to
  `videos/` and the heavy processor handles them like any other video.
- Skip-watermark copies no longer relabel the file: a `.webm`, `.mkv`, `.mov`
  or `.3gp` copied from `heavy/` keeps its original extension instead of being
  renamed `.mp4`, which mislabeled the container and made Discord reject it.
- Image formats sharp cannot reliably write back (`.avif`, `.bmp`, `.tiff`)
  are normalized to `.jpg` when watermarking, instead of keeping an extension
  that either fails to encode or does not match the actual output.

### 🌿 Changed

- Output-extension resolution is centralized in `getOutputExtension()` and
  shared by the normal pipeline and the heavy processor, so the declared
  extension always matches what the processor actually produces.

### Added

- Integration tests for the heavy processor covering skip-watermark copies,
  watermark promotion, oversized-file handling and the `_failed` quarantine.

## [1.7.2] 🐛 — 2026-08-11

### Added

- Unit test suite with Vitest: `pnpm test` (run once), `pnpm test:watch`
  (watch mode) and `pnpm test:coverage` (v8 coverage). Tests are co-located
  as `src/**/*.test.ts` and cover the pure utilities, file-system helpers,
  config loader, organizer, sender retry logic and channel resolution.
- `tsconfig.build.json` excludes test files from the production build so
  `dist/` ships only application code.
- The `verify` script now runs the test suite plus a full `typecheck`
  (`tsc --noEmit` over the whole `src/`, including tests), and the
  `pre-commit` hook runs `vitest run` alongside lint-staged and `tsc --noEmit`.

### Changed

- `build` now compiles with `tsc -p tsconfig.build.json`.
- Root-level config files (`vitest.config.ts`, `*.config.ts`) are ignored by
  ESLint, since they live outside the tsconfig `include` used for
  type-aware linting.
- Test files relax the type-aware `no-unsafe-*` rules for mock fixtures.

## [1.7.1] 🐞 — 2026-08-11

### 🐞 Fixed

- Orphaned ffmpeg processes: processes are now spawned detached and killed as
  a whole group on timeout/shutdown, so a `nice`-wrapped ffmpeg child is never
  left running when its wrapper is killed.

### 🌿 Changed

- Deduplicated child-process handling: `ffprobe`, video, GIF and version-check
  calls now share a single `runCommand()` helper (`src/utils/process.ts`) with
  process-tracking, hard timeouts, bounded output capture and optional `nice`.
- Encoder auto-detection is now asynchronous, so the boot-time micro-encodes
  no longer block the event loop.
- Image watermark opacity is applied natively via a `dest-in` composite
  instead of a manual per-pixel loop.
- Bounded the sent-file dedup registry so long watch-mode sessions cannot grow
  it without limit.
- `config.json` entries are now validated, warning and skipping invalid ones
  instead of silently passing them through.
- Unified log language to English.

## [1.7.0] 🌻 — 2026-08-11

### 🌿 Changed

- Hardware-accelerated video watermarking: the pipeline now auto-detects the
  best usable H.264 encoder at boot (`qsv` → `vaapi` → `nvenc` → `amf` →
  `libx264`), offloading encodes to the iGPU/GPU for less CPU, heat and wall
  time. Each hardware backend is validated with a micro-encode, so machines
  and Docker hosts without GPU passthrough degrade cleanly to software
  `libx264`. If a hardware attempt still fails on a specific file, it retries
  once with `libx264` before falling back to re-encoding the audio.
- New thermal/CPU knobs: `VIDEO_ENCODER` (force a backend, default `auto`),
  `VIDEO_FFMPEG_THREADS` (cap software encode threads), `VIDEO_NICE=1`
  (Linux: run ffmpeg at `nice -n 10`), and `SHARP_CONCURRENCY` (image
  watermark worker pool, default 4).
- Boot now logs the detected video encoder (`⚡ Video encoding: hardware` /
  `🧠 Video encoding: software`).
